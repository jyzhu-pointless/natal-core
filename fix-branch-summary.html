🎯 解决了什么

Bug：pop.update().presets(drive) 和 pop.update().modifiers(...) 不可用
根因①：_species 缺失 → RuntimeError
根因②：修复后，preset 对 config 的修改通过 _replace() 创建新 NamedTuple——只存在临时 Configurator 上，从未写回 Population

📥 for_population() — 统一的运行时构造入口

替换了散落在 3 个调用点的 object.__setattr__ 猴子补丁：

# 之前（3 处重复）
cfg = Configurator.for_config(config)
object.__setattr__(cfg, '_pop_ref', self)

# 之后
cfg = Configurator.for_population(pop)
# 内部设置 _pop_ref, _species, _registry
调用点之前之后
base_population.pyobject.__setattr__ hackConfigurator.for_population(self)
spatial update_demeobject.__setattr__ hackConfigurator.for_population(target)
spatial _dispatch_scalarobject.__setattr__ hackConfigurator.for_population(d)

🔄 跳过 _ConfigContext，直接写 Population

核心洞察：当 Configurator 绑定到 Population 时，不需要 adapter。Population 已有完整方法。

方法有 _pop_ref（更新路径）无 _pop_ref（构建路径，不变）
presets(drive)pop.apply_preset(drive)_ConfigContext adapter
modifiers(g=…,z=…)pop.add_*_modifier()_ConfigContext adapter
reconfigure_preset()清 Population 列表 → pop.apply_preset()清 Configurator 列表 → adapter
custom(temp=…)pop.set_config(self._config)只改 Configurator config

🗑 删除了什么

删除项原因
_state_nn / _config_nn / _registry_nn（6 个 property）与 _require_* 重复，用 self.state/config/registry 替代
_require_state / _require_config / _require_registry与 public property 逻辑重复
_sync_to_pop()不再需要——presets/modifiers 直接操作 Population
_write_back 概念不再需要——没有 Configurator→Population 同步

📦 修饰器存储拆分

修饰器现在有两个独立的来源，_rebuild_modifiers() 合并为引擎使用的派生列表：

属性类型写入者语义
_presetslist[(priority_id, GeneticPreset)]presets()preset 对象，按 priority 排序
_manual_gametelist[(id, name, GameteModifier)]modifiers()直接加的配子修饰器
_manual_zygotelist[(id, name, ZygoteModifier)]modifiers()直接加的合子修饰器
_gamete_modifiers派生_rebuild_modifiers()引擎只读——每次重建
_zygote_modifiers派生_rebuild_modifiers()引擎只读——每次重建

重建顺序：presets 按 priority_id 排序先产出 → 手动修饰器后追加。与 TODO #4 矩阵化重构兼容——矩阵化只改变单个修饰器的表示（callback → 矩阵），不影响来源拆分。
