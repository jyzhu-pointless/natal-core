_config 同一个 Python 对象 高 _replace() 后漂移 原地 ndarray 写入安全；_replace() 产生新对象后，只有被处理的 deme 拿到新引用

_hooks dict 同一个对象 中 理论上影响所有 deme，但运行时通常不修改

2. 两种修改模式

模式 A：原地 ndarray 写入

config.carrying_capacity[()] = 500
config.age_based_survival_rates[0,:] = [0.8,0.9]

config 的 id 不变。所有共享此对象的 deme 自动受益。
id() 去重正确且高效。

走此模式：competition(), AgeStructured reproduction/survival, fitness(), custom(), rebuild fitness .fill(1.0)

模式 B：_replace() 产生新对象

self._config = self._config._replace(
    is_stochastic=True,          # Python bool
    base_survival_f=0.8,        # Python float
    offspring_tensor=new,       # 换整个大数组
)

产生新的 NamedTuple。只有当前 deme 拿到新引用。其他共享旧 config 的 deme 被遗留。
id() 去重失效。

走此模式：setup(), Discrete survival/reproduction, rebuild_from/_refresh_modifier_maps, presets, modifiers

3. 允许 per-deme 差异的参数

构建时 — 全部可差异化

Builder 的 _detect_and_delegate() 对所有 isinstance(value, BatchSetting) 都做 per-deme 展开。但从语义上看：

类别参数合理 per-deme？典型用例
生态参数 carrying_capacity, low_density_growth_rate 是 不同区域食物量、增长率不同
生态参数 eggs_per_female, sex_ratio 是 不同区域繁殖条件不同
生态参数 per-age survival rates 是 不同区域死亡率不同
基因驱动 presets 是 分区域投放不同 drive
初始状态 individual_count 是 不同区域初始种群大小不同
遗传结构 genotype_to_gametes_map 否 所有 deme 共享同一物种
模式标志 stochastic 否 模拟模式应全局统一
年龄结构 n_ages, new_adult_age 否 所有 deme 应用同一年龄模型

运行时 — _SpatialUpdate._BATCHABLE_METHODS

当前列表：competition, reproduction, survival, initial_state, fitness, custom, setup。这些方法接受 batch_setting() 实现 per-deme 差异化。

4. 当前 Bug 清单

Bug #1：id(config) 去重 + _replace() → 其他 deme 拿不到新 config

影响：_dispatch_scalar 调用的所有模式 B 方法（survival/reproduction/setup in discrete model）、modifiers、presets
表现：同质群体中只有第一个被处理的 deme 拿到 _replace() 生成的新 config，其他共享旧 config 的 deme 保持旧值。
根因：id(config) 跟踪旧对象，但新对象只赋给了当前 deme。其他引用旧 config 的 deme 被当作"已处理"跳过。

Bug #2：Shared preset 对象的全局污染

影响：reconfigure_preset()
表现：setattr(preset, 'viability_scaling', 0.1) 修改的是所有 deme 共享的同一個 preset 对象。对 deme 2 做 reconfigure，deme 0 的 _presets 列表里同一个 preset 也被改了。下次任何触发 rebuild_from_presets() 的操作都会意外拿到新值。
根因：_clone() 浅拷贝：clone._presets = list(self._presets) 只复制列表，不复制列表内的 preset 对象。

Bug #3：presets() all-deme 路径不走 for_population

影响：pop.update().presets(drive)
表现：全 deme preset 应用走 for_config(config) → adapter 路径。preset 的 modifiers 和 fitness 写入了 config 数组，但 preset 没有被注册到任何 deme 的 _presets 列表。后续 reconfigure_preset 找不到它。
根因：for_config 不设 _pop_ref，Configurator.presets() 走 adapter 分支——只写 config，不调 add_preset()。

Bug #4：_hooks 字典在所有 clone 间共享

影响：运行时 hook 注册
表现：在某個 deme 上注册 hook 会影响所有其他 deme。
根因：_clone() 中 clone._hooks = self._hooks——直接引用，不复制。

5. 统一修复方案

5.1 统一 _dispatch_scalar：自动处理 _replace() 对象迁移

思路：当前 _dispatch_scalar 的 id(config) 去重对模式 A（原地写入）正确，对模式 B（_replace）失效。改为跟踪 old-config-id → new-config 映射——模式 A 不产生映射（new_config is old_config），行为不变；模式 B 产生映射并传播。

def _dispatch_scalar(self, method_name, kwargs):
    if self._deme is not None:
        cfg = self._pop.update_deme(self._deme)
        getattr(cfg, method_name)(**kwargs)
        return

    updated_configs: dict[int, object] = {}
    for d in self._pop.demes:
        old_config = d.config
        cid = id(old_config)
        if cid in updated_configs:
            d.set_config(cast(Any, updated_configs[cid]))
            continue
        cfg = Configurator.for_population(d)
        getattr(cfg, method_name)(**kwargs)
        new_config = d.config
        if new_config is not old_config:
            updated_configs[cid] = new_config

优势：模式 A 方法不受影响（共享 config 仍然有效去重）；模式 B 方法自动传播到同组其他 deme；保持 config 共享关系（同组 deme 仍然共享同一个新 config）。

5.2 _clone() 深拷贝 preset

思路：在 _clone() 中对 _presets 列表做深拷贝，让每个 deme 拥有独立 preset 对象。

import copy
clone._presets = [copy.deepcopy(p) for p in self._presets]

优势：reconfigure_preset 在单 deme 上只影响该 deme；rebuild_from_presets() 不会意外拿到其他 deme 的修改。
代价：内存微增（每个 preset 几十到几百字节），需验证与 preset 内部缓存的兼容性。

5.3 presets() all-deme 改用 for_population

思路：将 presets() all-deme 路径从 for_config(config) 改为 for_population(d)，触发 _pop_ref 路径——preset 被注册到各 deme 的 _presets 列表中。

def presets(self, *presets):
    if self._deme is not None:
        self._pop.update_deme(self._deme).presets(*presets)
        return self
    updated_configs: dict[int, object] = {}
    for d in self._pop.demes:
        old_config = d.config
        cid = id(old_config)
        if cid in updated_configs:
            d.set_config(cast(Any, updated_configs[cid]))
            continue
        Configurator.for_population(d).presets(*presets)
        new_config = d.config
        if new_config is not old_config:
            updated_configs[cid] = new_config

5.4 提取公共 _apply_to_demes 方法

思路：_dispatch_scalar、reconfigure_preset、presets 三处用了相同的 updated_configs 模式。提取为公共方法消除重复。

def _apply_to_demes(self, action: Callable[[Configurator], None]) -> None:
    """对每个唯一 config 执行 action，_replace() 产生的新 config 传播给同组 deme."""
    updated_configs: dict[int, object] = {}
    for d in self._pop.demes:
        old_config = d.config
        cid = id(old_config)
        if cid in updated_configs:
            d.set_config(cast(Any, updated_configs[cid]))
            continue
        cfg = Configurator.for_population(d)
        action(cfg)
        new_config = d.config
        if new_config is not old_config:
            updated_configs[cid] = new_config

6. 实施顺序

#步骤影响风险
1 _dispatch_scalar 统一用 updated_configs 修复所有模式 B 方法在 all-deme 路径的 bug 低 — 已在 reconfigure_preset 验证
2 presets() all-deme 改用 for_population 修复 preset 不注册到 _presets 中 — 需验证构建路径不受影响
3 _clone() 深拷贝 preset 修复共享 preset 全局污染 中 — 需验证 preset 缓存不冲突
4 提取公共 _apply_to_demes 消除 3 处重复 低
5 _hooks 在 clone 时拷贝 修复 hook 共享污染 中 — 可能影响 spatial hooks 机制
