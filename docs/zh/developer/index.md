# 开发者指南

这套指南面向需要理解、维护或扩展 NATAL Core 的开发者。阅读前应能按照[快速开始](../1_quickstart.md)构建并运行一个种群；这里从这一操作继续向下，追踪它如何变成数组、引擎会话和数值计算。

指南解释当前实现中的协作关系与约束。完整参数列表仍见 [API 参考](../api/index.md)。文中出现的私有函数是源码阅读入口，不构成公开 API 的稳定性承诺。

## 从两个样章开始

先读[一个模型从声明到结果的完整旅程](model_journey.md)，跟随同一个模型理解类型目录、概率表、运行会话和输出；再读[一次繁殖如何计算](reproduction.md)，逐项推导配对、产卵、遗传分配及各阶段的数量变化。

两个样章以“不先读源码也能理解过程、评估 agent 方案”为目标，包含完整数值案例和可区分不同实现的验收问题。下面的专题页保留为补充导读，其展开深度尚未全部达到样章标准。

## 阅读路线

| 顺序 | 章节 | 读完后能够回答 |
| --- | --- | --- |
| 1 | [架构与数据流](architecture.md) | 声明、运行状态、记录分别由谁持有？ |
| 2 | [模型编译与索引发布](model.md) | 为什么必须一起投影遗传表、初始状态和索引？ |
| 3 | [会话与一次 tick](runtime.md) | 一次运行如何推进，失败时停在哪里？ |
| 4 | [关键数值算法](algorithms.md) | 数学量如何对应到数组轴和内核函数？ |
| 5 | [Hook 与受控修改](hooks.md) | 修改何时可见，失败能撤销什么？ |
| 6 | [空间执行与迁移](spatial.md) | 多个 deme 如何共享布局、参数和时间线？ |
| 7 | [观测、历史与检查点](output.md) | 结果如何记录，哪些记录可以恢复？ |
| 8 | [修改与验证路线](development.md) | 改一个机制时，需要检查哪些相邻模块？ |

主线采用普通分阶段的离散世代模型：完整物种声明经过编译和发布，进入一个 Rust 会话；age-1 成体繁殖产生 age-0 后代，后代经过生存阶段成为下一代成体，最后从会话边界读取结果。年龄结构、空间和融合 Wright–Fisher 路径在相应章节单独说明。

## 如何配合源码阅读

先沿正文中的案例理解输入、中间状态和结果；源码与测试链接供你或 agent 在需要时核实实现，不要求先读完源码才能理解样章。源码和测试链接指向仓库 `main`；研究旧版本时应切换到同一提交的文档、代码和测试，避免混用版本。

每章的“验证入口”指出已有测试保护的行为，不表示这些测试在每次文档阅读或构建时自动执行。函数名、数组轴和边界条件用于定位事实；解释性计算不是可以直接运行的 Python 示例。

既有用户文档的“内部实现”和附录仍保留原入口。这套指南提供连续的开发者阅读路线，历史设计页面只提供演变背景。
