🔧 Configurator → Population 写回方案

replace_config · _sync_to_pop · _presets (future)

🛠 要解决什么问题

pop.update().presets(drive) 和 pop.update().modifiers(...) 当前不可用：

  • 崩溃：_species 缺失 → 已在 for_population() 中修复（设置 _species、_registry、_pop_ref）
  • 静默数据丢失：不崩溃后，presets() / modifiers() 内部通过 _replace() 创建了新 NamedTuple——但只存在临时 Configurator 上，从未写回 Population

数据丢失的根因

presets() 内部调用链：

_make_ctx()→ apply_preset_to_population(ctx, drive)→ _rebuild_config_maps(ctx)
↓ 内部调用 ctx.config._replace() 创建新 NamedTuple
_sync_from_ctx(ctx)→ self._config = ctx.config Configurator 拿到了新 config
Population._config ← 仍然是旧的！Configurator 被丢弃后，新 config 就丢了

✅ 解决方案：跳过 adapter，直接写 Population

核心洞察：当 Configurator 通过 for_population() 绑定到 Population 时，不需要 _ConfigContext adapter。Presets / modifiers 可以直接在 Population 上操作——Population 已经有完整的方法（apply_preset(), add_gamete_modifier(), refresh_modifier_maps()）。

有 _pop_ref（更新路径）：直接调 pop.apply_preset(drive) → Population 的 config 和 modifier lists 原地更新。Configurator 同步读回 self._config = pop.config。
无 _pop_ref（构建路径）：走 _ConfigContext adapter → _sync_from_ctx，和以前一样。

🗑 删除了什么

  • _sync_to_pop() — 不再需要。presets/modifiers 直接写 Population，custom() 用 set_config()
  • _write_back / replace_config — 全部取消。没有"Configurator→Population 同步"这回事了
  • set_config() 保留 — 仅给 custom() 用（custom() 在 Configurator 上 _replace 后需要写回）

✅ Phase 1 完成

presets()、modifiers()、reconfigure_preset()、custom() 在有 _pop_ref 时直接操作 Population，不再需要 _sync_to_pop / _write_back。无 _pop_ref 时（构建路径）保持 _ConfigContext adapter。
验证：pyright 0 errors · pytest 107 passed, 10 xfailed · pop.update().presets(drive) 不再崩溃，config 变更持久化。

📋 Phase 2：Population 维护 presets FUTURE

Phase 1 打通了写回，但有一个结构性问题：reconfigure_preset()（configurator.py:1249）靠名字前缀（"DriveName/"）在修饰器列表中查找旧条目。名字拼错、同名冲突都会出问题。如果 Population 自己维护 _presets 列表，就可以按对象 identity（is）查找。

Step 2-1：Population 加 _presets 列表

做什么：BasePopulation 新增 _presets: list[GeneticPreset]，跟 _gamete_modifiers / _zygote_modifiers 同一层。presets() 改为 append 到这个列表，而不再直接操作修饰器。

# base_population.py __init__ — 新增：
self._presets: list[GeneticPreset] = []

# base_population.py _clone() — 新增（和 modifier lists 一样的模式）：
clone._presets = list(self._presets)  # 浅拷贝列表，preset 对象共享引用

presets() 的行为变化：当前 presets(drive) 通过 _make_ctx() → apply_preset_to_population 直接把修饰器加到 _ConfigContext 的 gamete_modifiers 列表。改为先把 drive append 到 _presets，然后 _rebuild_modifiers() 从 preset 列表统一产出修饰器。

Step 2-2：拆分修饰器存储

做什么：preset 产物和手动修饰器分开存储，避免混在一起分不清来源。

属性存什么谁来写
_presetslist[GeneticPreset] — preset 对象presets() append
_manual_gamete_modifierslist[(id,name,fn)] — 直接加的配子修饰器modifiers(gamete_modifiers=[...]) extend
_manual_zygote_modifierslist[(id,name,fn)] — 直接加的合子修饰器modifiers(zygote_modifiers=[...]) extend
_gamete_modifiers派生——_rebuild_modifiers() 每次重建只读（引擎使用）
_zygote_modifiers派生——_rebuild_modifiers() 每次重建只读（引擎使用）
为什么这样分：reconfigure_preset 需要找到某个 preset 的产物，但当前它们和手动修饰器混在一个列表里。分开后，reconfigure_preset 直接在 _presets 里按 identity 找，不需要碰手动列表。

Step 2-3：_rebuild_modifiers() 合并逻辑

做什么：从两个来源重建实际生效的修饰器列表。preset 产物先生效，手动修饰器后追加。

def _rebuild_modifiers(self):
    """Rebuild _gamete_modifiers and _zygote_modifiers from sources."""
    self._gamete_modifiers.clear()
    self._zygote_modifiers.clear()

    # 1. 从 _presets 生成修饰器
    for preset in self._presets:
        # preset.gamete_modifier() / preset.zygote_modifier()
        # 产生 (id, name, fn) tuples
        gm_name = f"{preset.name}/gamete"
        zm_name = f"{preset.name}/zygote"
        self._gamete_modifiers.append(
            (self._next_modifier_id(), gm_name, preset.gamete_modifier(self))
        )
        self._zygote_modifiers.append(
            (self._next_modifier_id(), zm_name, preset.zygote_modifier(self))
        )

    # 2. 追加手动修饰器
    self._gamete_modifiers.extend(self._manual_gamete_modifiers)
    self._zygote_modifiers.extend(self._manual_zygote_modifiers)

    # 3. 重建 config maps
    _rebuild_config_maps_from_scratch(self)

调用时机：presets()、modifiers()、reconfigure_preset() 末尾都调用 _rebuild_modifiers()。每次都是全量重建——来源清晰，不担心增量更新的一致性问题。

Step 2-4：重写 reconfigure_preset()

做什么：不再按名字前缀（"DriveName/"）在修饰器列表中匹配，而是直接在 _presets 中按 is 找到 preset 对象，修改属性后全量重建。

位置：src/natal/configurator.py，reconfigure_preset()（line ~1249）。
