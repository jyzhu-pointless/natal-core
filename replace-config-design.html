Configurator → Population 写回设计

fix/runtime-crash-and-data-corruption 分支 · 当前状态

🛠 原始问题

pop.update().presets(drive) 和 pop.update().modifiers(...) 不可用：

  1. 崩溃：_species 缺失 → RuntimeError
  2. 静默数据丢失：不崩溃后，preset 通过 _replace() 创建的新 NamedTuple 只存在临时 Configurator 上

✅ 已实施

1. for_population() — 统一的运行时构造入口

消除 3 个调用点的 object.__setattr__ 猴子补丁，集中在 Configurator 的一个工厂方法里。

Configurator.for_population(pop)
# 内部：包装 config + 设 _pop_ref + _species + _registry

2. 跳过 _ConfigContext，直接写 Population

当 _pop_ref 存在时，presets() / modifiers() / reconfigure_preset() 直接操作 Population 的现有方法——不需要 adapter、不需要 sync、不需要 write-back。

方法有 _pop_ref（更新路径）无 _pop_ref（构建路径）
presets(drive)pop.apply_preset(drive)_ConfigContext adapter
modifiers(g=,z=)pop.add_gamete_modifier() + pop.refresh_modifier_maps()_ConfigContext adapter
reconfigure_preset()清 Population 列表 → pop.apply_preset()清 Configurator 列表 → adapter
custom()pop.set_config(self._config)只改 Configurator 的 config

3. 清理冗余访问器

删除：_state_nn / _config_nn / _registry_nn（6 个 property）· _require_state / _require_config / _require_registry（3 个方法）· _sync_to_pop()（不再需要）

4. 修饰器存储拆分

修饰器现在有两个独立来源，_rebuild_modifiers() 按优先级合并（presets 先，手动后）：

属性类型写入者
_presetslist[(priority_id, GeneticPreset)]presets()
_manual_gametelist[(id, name, GameteModifier)]modifiers()
_manual_zygotelist[(id, name, ZygoteModifier)]modifiers()
_gamete_modifiers派生（_rebuild_modifiers 重建）引擎只读
_zygote_modifiers派生（_rebuild_modifiers 重建）引擎只读
