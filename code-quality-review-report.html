💥 运行时更新崩溃矩阵

根因：_create_configurator() 和 _SpatialUpdate 都使用 Configurator.for_config()，它只包装 config 对象，不设置 _species。 之后 fitness()、presets()、modifiers()、reconfigure_preset() 都通过 _make_ctx() 触发守卫。 空间路径额外有 _dispatch_scalar → set_param 路由问题。

🔑 关键结论

  • 运行时真正需要的 reconfigure_preset() 和 fitness() — 在任何群体类型上都崩溃
  • presets() 和 modifiers() 理论上是构建时 API（不应走 update()），但错误消息暗示设计预期能从 update() 调用
  • 空间路径额外有 2 个崩溃 — setup(bool) 和 survival(adult_survival) — 根因是 _dispatch_scalar 把一切路由给 set_param
  • 修复入口：base_population.py:480 — _create_configurator() 中补设 _species

🔧 修复计划

这些 bug 有一个共同模式：都是重构过程中"协议不一致"的产物。Configurator 有三条构造路径（from_species、for_config、子类直接构造），每条路径初始化的属性不同。update() 走了 for_config 路径，但 presets()/fitness() 等方法是按 from_species 路径的假设写的。
