架构变更

1. Population：modifier 存储模型重构

变更之前之后
_rebuild_modifiers() 私有方法，只重建 modifiers public rebuild_from_presets()，统一重建 modifiers + fitness
manual modifier 路径 add_gamete_modifier() → 全量重建 轻量 直接 append → _refresh_modifier_maps()
_presets 存储 list[GeneticPreset]（空壳） list[GeneticPreset]（被 presets() 写入）
_manual_gamete 空壳 被 modifiers() 写入

2. Configurator：DiscreteConfigurator 独立

之前：共享 _xxx_impl

DiscreteConfigurator.survival()
  → _survival_impl(female_age0=...)
    → set_param("survival.female_age0")
    → 写入 age_based_survival_rates[0, 0]

引擎读取: cfg.base_survival_f  ← 标量过期！

之后：独立实现

DiscreteConfigurator.survival()
  → self._base_survival_f = val
  → _replace(base_survival_f=val)
  → set_config()  ← 运行时同步

build()
  → 从存储值提取标量到 config
  → 调用 super().build()

核心原则：离散引擎只读标量（base_survival_f、female_mating_rate 等），不读数组（age_based_survival_rates 等）。离散实现直接操作引擎真正读取的数据，不再通过共享 _impl 绕路。

3. 空间层：_dispatch_scalar 重构

之前：逐参数 set_param

for key, val in kwargs.items():
    if isinstance(val, (float, int, bool)):
        set_param(config, f"{method}.{key}", val)
    # list/dict/callable → 静默丢弃
    # Python bool → TypeError
    # 2D 数组 → ValueError

之后：完整方法调用

cfg = Configurator.for_population(d)
getattr(cfg, method_name)(**kwargs)
# 所有参数类型正确处理
# 离散模型错误参数 → TypeError 明确报错

关键设计决策

1. 为什么让 rebuild_from_presets 成为 public？

Configurator 需要调用它来重建 preset → modifiers + fitness。之前是 private，每个调用点都要 pyright: ignore[reportPrivateUsage]。被外部频繁调用的方法天然该是 public。

2. 为什么 DiscreteConfigurator 不再调共享 _xxx_impl？

共享 _impl 把两个模型的数据路径混在一起——离散写数组但引擎读标量，导致"写对了地方但读不到"的过期问题。独立实现后，离散直接操作引擎真正读取的数据。

3. 为什么 _dispatch_scalar 改为完整方法调用？

set_param 逐参数写入无法处理 Python bool、list/dict/callable、2D 数组。委托给 Configurator 方法后，所有参数类型得到正确处理，离散模型不接受年龄结构参数会立即 TypeError。

4. 为什么 K 自动检测只在构建时运行？

_competition_impl 在没传 K 时会从 initial_individual_count 自动推断。这对构建时合理（用户设了初始状态但忘了设 K），但对运行时更新是破坏性的——会覆盖掉已配置的 K。守卫 _pop_ref is None 精确区分两者。
