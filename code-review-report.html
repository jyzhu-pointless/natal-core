CRITICAL Fix 1: reconfigure_preset() 条目重复

问题

当用户调用 pop.update().reconfigure_preset(drive, efficiency=0.5) 时：

  1. 修改 preset 属性
  2. 按 prefix 从 self.gamete_modifiers 清理旧条目
  3. 调用 self.presets(preset) → 走 _pop_ref 路径 → pop.add_preset(preset)
  4. 同一 preset 被追加到 _presets 列表第二次
  5. rebuild_from_presets() 遍历时 modifier 和 fitness 双重应用

结果：静默数据损坏 — 模拟结果偏离正确值，无任何警告或错误。

修复方案

策略：不重入 presets()，直接调用 pop.rebuild_from_presets() 进行全量重建。 
def reconfigure_preset(self, preset: GeneticPreset, **changes: object) -> Self:
    # 1. 属性存在性检查 — 防止打错字静默创建 stray attribute
    for attr, value in changes.items():
        if not hasattr(preset, attr):
            raise AttributeError(
                f"{type(preset).__name__} {preset.name!r} has no "
                f"attribute {attr!r}. Cannot reconfigure a non-existent "
                f"parameter — this would silently create a stray attribute "
                f"on the preset object."
            )
        setattr(preset, attr, value)

    # 2. 直接全量重建 — 不重入 presets()，避免重复追加
    if self._pop_ref is not None:
        pop = self._pop_ref
        pop.rebuild_from_presets()
        self._config = pop.config
    else:
        raise RuntimeError(
            "reconfigure_preset() requires a live Population. "
            "Use pop.update().reconfigure_preset(...) or "
            "Configurator.for_population(pop).reconfigure_preset(...)."
        )

    # 3. 同步平衡指标
    from natal.engine.simulation.age_structured import sync_equilibrium_metrics
    sync_equilibrium_metrics(self._config)
    return self

🔧 重构设计：DiscretePopulationConfig 废弃源数组

目标：消除 DiscretePopulationConfig 中「同一数据两份拷贝」的同步问题。让 0-d 标量成为唯一真相源，删除冗余的 2D 源数组字段。

🧠 设计演变：从累积清理到全量重建

旧设计：累积式 modifier 列表

presets(drive) → self.gamete_modifiers.append(...) → self.zygote_modifiers.append(...)

modifier 列表是累积状态。每次 presets() 调用追加条目。要修改 preset 参数，必须先"撤回"旧条目（按 prefix 匹配清理），再重新追加。

这带来了 prefix 清理的复杂性、重入风险、以及无法区分「preset 来源的 modifier」和「手动添加的 modifier」。

新设计：源列表 + 全量重建

源列表（Source of Truth）
_presets: list[GeneticPreset]
_manual_gamete: list[...]
_manual_zygote: list[...]
→
派生列表（Derived）
_gamete_modifiers
_zygote_modifiers
config.offspring_tensor
config.viability_fitness

rebuild_from_presets() 流程

def rebuild_from_presets(self) -> None:
    # 1. 重置 fitness 为中性值 (1.0)
    self._config.viability_fitness.fill(1.0)
    self._config.fecundity_fitness.fill(1.0)

    # 2. 清空派生 modifier 列表
    self._gamete_modifiers.clear()
    self._zygote_modifiers.clear()

    # 3. 按 priority 排序 preset，逐个应用
    for preset in sorted(self._presets, key=lambda p: p.priority):
        preset.apply(self)        # → 向派生列表追加 modifier
        apply_preset_fitness_patch(self, preset)  # → 写 fitness tensor

    # 4. 追加手动添加的 modifier
    self._gamete_modifiers.extend(self._manual_gamete)
    self._zygote_modifiers.extend(self._manual_zygote)

    # 5. 刷新 modifier maps（offspring_tensor 等）
    self.refresh_modifier_maps()

为什么 prefix 清理不再需要

旧设计中，modifier 列表是唯一真实来源——要修改 preset 就必须操作这个列表（先删再加）。

新设计中，_presets 才是真实来源。reconfigure_preset() 修改 preset 属性后，直接调用 rebuild_from_presets() 从头构建派生列表。旧的派生数据自动丢弃，不存在"撤回"的概念。

这是「派生数据」和「累积状态」的设计区别——派生数据可以由源任意次重建，不需要增量维护。
